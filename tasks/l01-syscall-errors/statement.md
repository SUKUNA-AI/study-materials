## Коротко
Напиши три функции, которые превращают код ошибки (errno) в исключение C++ без потери кода.
Затем посмотри через `strace`, какие системные вызовы делают обычные программы.

## Зачем
Тот же приём понадобится для `cudaError_t` в обёртках твоих ядер.

## Вход и выход
```cpp
long check(long ret, const char* what);    // ret == -1 → исключение, иначе вернуть ret
void check_rc(int rc, const char* what);   // rc != 0 → исключение с кодом rc
std::int64_t file_size(const char* path);  // размер обычного файла в байтах
```
- Исключение — `std::system_error(код, std::generic_category(), what)`.
- `file_size`: каталог → код `EISDIR`, другой необычный файл → `EINVAL`, в `what()` — путь.
- Функции — в `namespace lab::sys`; Linux, glibc, C++23.

| вход стенда | ожидается |
|---|---|
| `{"case": "check_errno", "scenarios": ["open_missing"]}` | `{"errno": "ENOENT", "category": "generic", "what_has": true}` |

## Как проверяется
- `check_errno` (2 + 3 + 1 балл): `open` несуществующего файла → `ENOENT`; ошибки `EBADF`, `EINVAL`, `EISDIR`, `ENOTDIR`, `EEXIST`; заранее выставленный `errno` (`EIO`).
- `check_ok` (1 + 2): обычные значения проходят без изменений, в том числе отрицательные кроме −1 и больше 2³¹.
- `check_rc` (3): коды pthread и настоящий `pthread_mutex_*`; `errno` не трогается.
- `file_size` (2 + 1 + 3 + 2): файлы 0, 1, 4097 и до 100 000 Б; ошибочные пути (нет файла, каталог, `ENOTDIR`, пустая строка, `/dev/null`); 300 вызовов при лимите 256 дескрипторов.
- Категория ошибки — только `std::generic_category()`. Утечку дескриптора стенд видит по `/proc/self/fd`.
- Linux-песочница: пользователь nobody, запись только в `/tmp`, без сети. Сборка: g++ 14 `-std=c++23` с ASan и UBSan, затем `-O2`. Лимит — 2 с и 256 МиБ на тест.
