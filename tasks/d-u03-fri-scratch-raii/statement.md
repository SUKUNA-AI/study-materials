# Временный массив без ручного delete

*Исправь UB (Т06) · задача дня U03, запас (Пт) · судья, 16 тестов · уровень: самостоятельно*

## Коротко
Почини `scratch_total(v, cancel)`: заготовка неверно освобождает временный массив и теряет его при исключении.
Пусть массивом владеет объект, а не ручной `delete`.

## Зачем
Временные буферы под ядро освобождаются и при обычном выходе, и при исключении — это и есть RAII.

## Вход и выход
```cpp
inline std::int64_t scratch_total(std::span<const int> v, bool cancel);
```
- Создай временный массив длины `v.size()`, скопируй в него `v`, верни сумму его элементов.
- При `cancel == true` после копирования брось `std::runtime_error("cancel")`.
- Массивом владеет `std::unique_ptr<int[]>` или стандартный контейнер. Длина — до 1000.

| `v` | `cancel` | результат |
|---|---|---|
| `[7]` | нет | `7` |
| `[3, -2, 3]` | нет | `4` |

## Как проверяется
- 4 открытых и 12 скрытых тестов, 1 балл за тест.
- Скрытые: `cancel == true` на разных длинах, крайние значения `int` (сумма шире `int`), длина 1000.
- Ошибку освобождения ловит ASan уже на открытых тестах. Утечку при исключении ловит LSan в сборке g++; MSVC ASan утечки не ловит. Для своей проверки на Windows включи `ASAN_OPTIONS=alloc_dealloc_mismatch=1`.
