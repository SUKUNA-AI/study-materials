# Как проверить работу и что отправить

Для задачи нужен один собственный исходник по пути из «Сдать». Для чтения, опыта
или проекта — перечисленные в карточке исходники, заметка и команды. Заголовок
`solution.h` задаёт интерфейс; функцию, свои примеры и свою сборку пишешь сам.

1. Сохрани файлы в рабочей папке (workspace) по указанному пути.
2. Проверь работу. Для первой CPU-задачи из корня workspace:

   ```text
   python tools/study.py check g-u01-01-sum-even --source cpp/u01/g-u01-01-sum-even/solution.cpp
   ```

   Это локальные публичные тесты через `judge check-public`, без сети и входа на
   сервер. Нужны клиент judge, компилятор и поддержанный профиль среды; точные
   доступные возможности показывает `python tools/study.py doctor`. Для Linux
   проверяется Docker и закреплённый образ. Если профиль не поддержан, команда
   сообщает ограничение; отсутствие запуска не является успешной проверкой.
3. Сохрани свой commit и отправь его в свой GitHub workspace. В текст ответа
   на портале коротко напиши: что проверил, команда/ID запуска, результат и
   оставшийся вопрос. В поле ссылки приложи файл, папку или PR с этой работой.

Для одного исходника нужна ссылка GitHub на файл (`blob`) в конкретном коммите:
`https://github.com/<владелец>/<workspace>/blob/<commit>/cpp/u01/g-u01-01-sum-even/solution.cpp`.
Для нескольких файлов — ссылка на папку (`tree`) этого коммита либо PR с ними.
На GitHub открой нужный файл/папку после push и скопируй адрес; постоянная ссылка
на commit сохраняет именно проверенную версию. В PR перечисли пути и команду.
Поле текста содержит краткое пояснение, поле ссылки — адрес работы на GitHub.

Для формальной серверной попытки нужна сеть и авторизация:
`python tools/study.py submit g-u01-01-sum-even --source cpp/u01/g-u01-01-sum-even/solution.cpp`.
Команда `check ... --remote` явно выбирает серверную проверку. Локальные публичные
тесты, полная серверная проверка и учебное ревью имеют отдельные результаты.
Исправленная отправка создаёт новую попытку; один зелёный тест не означает accepted.

Если тест не прошёл, сократи неверный вход и сравни его с конкретным пунктом
контракта. Сохрани команду и вывод. По окончании времени оставь текущую попытку
и вопрос, не добавляя себе скрытый второй слот.

CUDA: наличие `nvcc` подтверждает только компилятор. Компиляция, запуск на GPU,
`compute-sanitizer` и измерение скорости — разные проверки. CPU-модель индексов
не подтверждает запуск ядра. На CPU-ноутбуке доступны теория и трассировка;
GPU-проверку выполняй в поддержанном GPU-профиле, иначе укажи блокер. Порог скорости
нужен только там, где он явно указан в условии.
