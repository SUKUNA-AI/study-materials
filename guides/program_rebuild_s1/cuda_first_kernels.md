# CUDA U01–U04: от модели исполнения к двум маленьким ядрам

Основной учебник — PMPP, 5-е издание, русский перевод ученика: глава 1 PDF 42–71; глава 2 PDF 73–106; глава 3 PDF 107–135. Нумерация — из `content/books/pmpp_5e_ru.md`. Актуальные принятые версии среды — `content/VERSIONS.md`; в отчёте исполнения записываются реальные версии, а не просто копия этого документа.

На Linux-ноутбуке без NVIDIA — только теория, адресная арифметика и CPU-примеры. CUDA запускается на домашнем Windows-ПК. Host-код — C++23; `.cu` — C++20. Шаблон проекта не содержит готового CMake: сборку пишет ученик. Интеграция с весами модели, roofline-паспорт модели, FP8/NVFP4, cuBLAS и Tensor Cores сюда не входят.

## 1. U01: паспорт и границы среды — 60 минут

5 минут: выпиши, где будет выполняться host-код, а где ядро. 15 минут: выборочное введение PMPP — гетерогенная система и стоимость обмена. 25 минут: проверь доступность `nvidia-smi`, `nvcc --version`, host-компилятора; собери небольшой device-query по документации runtime API. 15 минут: сохрани имя устройства, compute capability, число SM и версии в `environment.md`.

Ничего не устанавливай с административными правами по ходу учебного опыта. Если Toolkit или поддерживаемого host-компилятора нет, зафиксируй блокер. Значение «CUDA Version» в `nvidia-smi` не подставляй вместо версии установленного `nvcc`. Отдельно проверь фактический стандарт языка `.cpp` и `.cu`. Непроверенную среду не помечай зелёной.

## 2. U02: путь данных и ошибки — 50 + 40 минут

В теории (50 минут) нарисуй жизненный цикл трёх буферов: host-данные, память устройства, возвращённый результат. Для каждого этапа укажи владельца и момент, когда разрешено освобождение. 5 минут прогноз; 25 чтение; 15 схема и два разбора ошибочного порядка; 5 объяснение без книги.

Практика дома (40 минут): собственный небольшой host-driver выделяет буфер, переносит учебные данные и возвращает их обратно; kernel ещё не нужен. Проверяй каждый runtime-вызов и все пути очистки. Ошибка API — отдельный результат, не пустая успешная таблица. Сначала запиши ожидаемые байты и только потом выполняй копии. Итог — равенство содержимого и лог ошибок, не замер скорости PCIe.

## 3. U03: одномерная сетка и vector add — 50 + 70 минут

Теория: 5 минут прогноз, 25 минут глава 2, 15 минут трассировка индексов, 5 минут объяснение. Разобранный пример адресации: в сетке из двух блоков по четыре потока блок 1 и поток 2 обозначают логический индекс 6. При длине массива 7 этот индекс существует, а следующий уже нет. После разбора закрой пример и протрассируй другую длину и конфигурацию.

На GPU-слоте 35 минут занимает пакет `k-s1-vadd-basics`: один поток — один элемент, защита хвоста, конечные FP32-значения; автопроверка результата без порога пропускной способности. Остальные 35 минут — собственный host-driver, проверка ошибок запуска и завершения, `compute-sanitizer --tool memcheck`, запись команд и результата. Пустой вход не требует запуска с нулевой сеткой. Сетку и блок не смешивай с числом SM.

Сдаётся `solution.cu` пакета и отдельно собственный запуск с проверкой на CPU. `cudaGetLastError` сразу после запуска и проверка результата синхронизации наблюдают разные классы ошибок. Один успешный запуск без проверки результата не считается готовым ядром.

## 4. U04: матрицы и наивное умножение — 50 + 70 минут

Это явное дополнение ученика к первоначальному плану. Берём только предварительное знакомство с двумерными координатами из главы 3. Тайлинг и shared memory из главы 5 остаются на U07; производительная лестница SGEMM — позже.

Теория, 50 минут: 5 минут сформулировать размеры; 20 минут чтение row-major и двумерной сетки; 20 минут CPU-эталон и адресная трассировка; 5 минут самопроверка. Для произведения A[M,K] × B[K,N] результат имеет форму C[M,N]. Номер строки и столбца — разные координаты; длина общей оси K не равна ширине результата N в общем случае.

Разобранный пример размещения, не решение ядра: у row-major массива 2×3 элемент строки 1, столбца 2 имеет смещение 5 элементов. Для матрицы B размера K×N шаг строки равен N. На бумаге выдели строку A и столбец B, которые участвуют в одном выходном значении. Затем закрой пример и разметь прямоугольные A[3,2] и B[2,4]. Не ограничивай проверку квадратными матрицами: они скрывают перепутанные размеры.

GPU-слот: 60 минут — `k-s1-matmul-naive`; 10 минут — протокол проверки. Один поток вычисляет один выходной элемент последовательным циклом по K. M/N/K могут быть нулевыми. При K=0 существующие выходы должны быть записаны нулями; при M=0 либо N=0 выхода нет и запуск не требуется. Входы не пересекаются с выходом и не меняются.

Проверяй прямоугольные формы, неполные блоки, K=0 и дробные числа. CPU-эталон аккумулирует в FP64; допуск пакета `|got-ref| <= 1e-5 + 1e-5*|ref|`. NaN/Inf результата не принимаются. Побитового совпадения матричного произведения и ускорения относительно библиотеки этот пакет не требует.

## Честная приёмка

В каждом логе: commit решения, ОС, GPU, Toolkit, host-компилятор, стандарт языка, архитектура сборки, команды и исходы. CPU-модель адресации не проверяет CUDA runtime, ABI, nvcc, реальный параллелизм или корректность вызовов устройства. До настоящего GPU-прогона такой результат помечается «CPU-модель проверена; GPU не проверен».

Источники API: NVIDIA CUDA Programming Guide и CUDA Runtime API. Профилирование, подбор лучшей сетки, проценты пика памяти и утверждения «все decode-ядра memory-bound» в первые четыре недели не требуются.
