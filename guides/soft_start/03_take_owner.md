# Перед задачей: передаётся владелец, не объект

5 минут внутри двадцатиминутной задачи U05.D3. Предпосылки: U03.T17, U04.T8.
Различай два адреса: адрес владельца и адрес объекта, которым он управляет.

```cpp
#include <cassert>
#include <memory>
#include <utility>
int main() {
    auto source = std::make_unique<int>(17);
    const int* address = source.get();
    auto receiver = std::move(source);
    assert(!source);
    assert(receiver.get() == address && *receiver == 17);
}
```

`std::move` сам ничего не переносит: он меняет категорию выражения. Здесь
выбирается перемещающий конструктор `unique_ptr`: новый владелец забирает тот же
указатель, а исходный становится пустым. Сам `int` не пересоздаётся.
Пустоту источника гарантирует именно контракт `unique_ptr`, не любое перемещение
произвольного класса или контейнера.

Прогноз R2: можно ли здесь заменить вторую строку создания владельца на
`auto receiver = source;`? Это ошибка компиляции или ошибка во время выполнения?

Теперь примени тот же механизм к параметру-ссылке `take_job`. Имя параметра в теле
функции — lvalue. Не выдавай создание нового `Job` за передачу старого объекта.
Справка по карте: Грегуар, гл. 7, стр. PDF 460–466; гл. 9, 551–560.
Первоисточник: [конструкторы unique_ptr](https://eel.is/c++draft/unique.ptr.single.ctor).
