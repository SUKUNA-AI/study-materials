# Перед задачей: пустой диапазон — отдельное состояние

5 минут внутри двадцатиминутной задачи U06.D1. После U05.T7, U05.T8, U05.T10.
Здесь разобрана более простая функция: вернуть первый элемент, не минимум и максимум.

```cpp
#include <array>
#include <cassert>
#include <optional>
#include <span>
std::optional<int> first(std::span<const int> xs) {
    if (xs.empty()) return std::nullopt;
    return xs.front();
}
int main() {
    const std::array<int, 2> xs{0, -4};
    assert(first(xs).value() == 0);
    assert(!first({}).has_value());
}
```

`span<const int>` даёт читать элементы, но не изменять их через представление.
`optional<int>` различает число, в том числе ноль, и отсутствие числа. Поэтому
сначала проверяется пустота и только затем читается элемент. Тот же порядок
действий нужен перед разыменованием итератора алгоритма.

Прогноз R3: почему возврат `0` вместо `nullopt` сделал бы два вызова в примере
неразличимыми по содержимому результата?

В своей `extrema` выбери простой цикл или библиотечный алгоритм. Разобранный пример
не диктует способ поиска границ; он объясняет контракт пустого входа.
Справка по карте: Грегуар, гл. 1, стр. PDF 135–137 (`optional`);
гл. 18, 1200–1202 (`span`). Это справка, не повторное обязательное чтение главы.
