# Перед stable_ids: факт встречи и порядок — разные данные

5 минут внутри двадцатиминутной задачи U08.D1, до написания решения. Предпосылки:
U05.T10 (контейнер), U06.T21 (обход, алгоритмы и справка по хеш-таблицам).
Здесь строятся отметки «новое значение», а не итоговый список уникальных значений.

```cpp
#include <cassert>
#include <unordered_set>
#include <vector>
int main() {
    const std::vector<int> input{9, 2, 9};
    std::unordered_set<int> seen;
    std::vector<bool> flags;
    for (int x : input) flags.push_back(seen.insert(x).second);
    assert((flags == std::vector<bool>{true, true, false}));
}
```

`insert` возвращает пару: итератор и признак фактической вставки. При первом `9`
признак истинен, при `2` тоже, при повторном `9` ложен. Множество помнит факт
встречи. Порядок обхода множества не является порядком входа; поэтому выходную
последовательность формируют при чтении входа, а не обходом `seen` после него.

Прогноз R5: какие отметки получатся для `[4, -1, 4, 0, -1]`? Сначала пройди строки
вручную. Затем закрой пример и решай `stable_ids`: тебе нужен список значений,
а не список флагов. Не используй сортировку как способ «упростить» контракт.
