## 1. Как устроен один учебный шаг

Открой «Неделя», найди сегодняшний день и открой учебную карточку. Сначала прочитай цель и ожидаемый результат. Чтение, решение задачи и отправка ответа — разные действия. Открытие условия не должно означать начало решения: в обновлённом интерфейсе для этого есть отдельная кнопка «Приступить».

У задачи с автопроверкой сначала посмотри контракт: что передают функции, что она должна вернуть и какие случаи допустимы. Затем ответь на «Проверь, что понял». Это проверка условия, а не экзамен по новой теме. После начала работы редактор уже содержит сигнатуру функции. Не добавляй `main`: проверяющий стенд вызывает функцию сам. Отправка запускает проверку; неверный ответ не стирает код.

В среду мы не сдаём самостоятельную задачу с пустого листа. Найди блок решения и прочитай, как его открыть. Нажимать «Приступить» в среду не нужно: примеры для разбора приведены ниже. В четверг будет маленькая задача из готовых строк. Вариант с `judge pull` нужен только для работы в CLion; он не является обязательным входом в обучение.

Проверь, что знаешь, где открыть терминал своей IDE и увидеть версию компилятора. Полную сборку лабораторий своим CMake делаем в субботу. Сейчас не нужно чинить сразу всю инфраструктуру и решать задачу одновременно. Если среда не работает, запиши команду и текст ошибки отдельно: ошибка окружения не равна ошибке в C++.

## 2. Значение, тип и последовательность действий

Переменная — именованный объект, в котором хранится значение определённого типа. Для первого примера достаточно целых чисел `int`.

```cpp
int requests = 3;
int extra = 2;
requests += extra;
```

Первая строка создаёт `requests` со значением 3. Вторая создаёт независимый объект `extra` со значением 2. Третья читает оба значения и записывает сумму в `requests`. После неё `requests` равен 5, а `extra` всё ещё равен 2. Знак `=` в присваивании означает запись результата, не математическое равенство.

Не держи весь пример в голове. Сделай таблицу: «после строки — requests — extra». Пока объект ещё не объявлен, поставь прочерк. Это трассировка (tracing): мы следим за состоянием программы по шагам.

Условие выбирает действие:

```cpp
int jobs = 4;
if (jobs > 3) {
    jobs = 3;
}
```

Сначала сравниваем 4 и 3. Условие истинно, поэтому выполняется тело и `jobs` становится 3. При исходном значении 2 тело было бы пропущено. Фигурные скобки объединяют строки в блок. Не смешивай `>` («строго больше») и `>=` («больше или равно»).

Самопроверка S1: запиши значение после каждой строки, пока не запускаешь код.

```cpp
int value = 2;
int copy = value;
value = 7;
copy += 1;
```

Сначала объясни, сколько здесь объектов. Затем проверь ответ отдельно. Если ошибся, вернись к строке, на которой перестал различать два объекта.

## 3. Функция: вход, локальная работа, результат

```cpp
int capped_at_three(int value) {
    if (value > 3) return 3;
    return value;
}
```

У функции имя `capped_at_three`, один параметр `int value` и возвращаемый тип `int`. Параметр здесь передан по значению: функция работает со своей копией числа. Для входа 8 срабатывает первый `return`: результат — 3. Для входа 2 условие ложно, результат возвращает вторая строка: 2. После `return` выполнение этого вызова заканчивается.

```cpp
int original = 8;
int result = capped_at_three(original);
```

`result` равен 3, а `original` остаётся 8. Получить результат и изменить исходный объект — не одно и то же. В следующей задаче ты соберёшь похожую функцию, но с другим правилом: обнулить отрицательное число. Не копируй сравнение механически, сначала прочитай её контракт.

Самопроверка S2: что возвращает `capped_at_three(3)` и какая строка `return` выполняется? Самопроверка S3: изменится ли `original`, если результат вызова вообще не сохранить?

**Стоп на сегодня.** Закрой текст и объясни три вещи: что хранит переменная, когда выполняется тело `if`, что делает `return`. Не нужно читать вперёд, пока эти действия снова не стали понятными.

## 4. Воскресенье U01: ссылка и указатель без лишних усложнений

Ссылка (reference) даёт другое имя существующему объекту:

```cpp
void set_to_three(int& value) {
    value = 3;
}

int original = 8;
set_to_three(original);
```

Здесь `value` внутри функции обозначает тот же объект, что `original` снаружи. После вызова исходное число стало 3. Сравни с предыдущей функцией: добавленный `&` меняет смысл параметра. Тип `void` означает, что функция не возвращает значение; результат её работы — изменение объекта.

Указатель (pointer) — отдельный объект, хранящий адрес:

```cpp
int jobs = 5;
int* ptr = &jobs;
*ptr = 6;
```

В `&jobs` берём адрес. В `*ptr = 6` обращаемся к объекту по этому адресу и меняем `jobs`. Указатель может быть `nullptr`; обращаться через такой указатель к значению нельзя. В этом примере адрес действителен всё время использования: `jobs` ещё существует.

`const int*` разрешает читать число через указатель, но не менять его этим путём. Это не означает владение памятью. Время жизни (lifetime) — отдельный вопрос: объект должен существовать, когда ты к нему обращаешься. Сначала научимся видеть живой объект; динамическая память и владельцы будут дальше по программе.

Самопроверка S4: чем различаются параметры `int value` и `int& value`, если тело содержит `value = 3`? S5: можно ли читать `*ptr`, когда `ptr == nullptr`? Объясни без запуска опасного кода.

## 5. Понедельник U02: строка и её представление

`std::string` хранит собственные символы. `std::string_view` — представление (view) существующей последовательности: его нужно использовать, пока соответствующие символы остаются доступны и адрес не инвалидирован.

```cpp
#include <string>
#include <string_view>

std::string owner = "abcd";
std::string_view view = owner;
std::string independent{view};
owner[0] = 'X';
```

Здесь представление видит изменение первого символа, а `independent` содержит независимую копию. Мы не увеличивали длину `owner` и не меняли его буфер, поэтому именно в этом примере представление остаётся действительным. В общем случае после изменений строки это нужно проверять отдельно.

Метод `view.substr(pos, count)` задаёт начальную позицию и число символов. Например, для `"abcd"` вызов `substr(1, 2)` задаёт фрагмент `"bc"`. Это всё ещё представление. Чтобы вернуть собственную строку, создаём `std::string` из этого представления. Если запрошенная длина больше оставшегося текста, берётся доступный остаток. Начальная позиция за концом — другой случай, который может привести к исключению; в задаче начала строки позиция равна нулю.

Не превращай представление в C-строку через один `data()`: тогда ты теряешь явную длину. Встроенный нулевой байт — обычный байт строки с известной длиной. В задаче считаем байты, а не символы Unicode.

## 6. Подготовка к среде и четвергу U02: цикл и счётчик

Сначала отдели количество итераций от результата:

```cpp
int sum = 0;
for (int i = 1; i <= 3; ++i) {
    sum += i;
}
```

У цикла три части: начальное значение, условие продолжения и шаг после тела. Значения `i` в теле — 1, 2 и 3; суммы после этих шагов — 1, 3 и 6. При `i == 4` условие ложно. Тело не исполняется.

Теперь похожий, но другой пример: посчитаем отрицательные элементы массива.

```cpp
#include <cstddef>

std::size_t count_negative(const int* values, std::size_t n) {
    std::size_t count = 0;
    for (std::size_t i = 0; i < n; ++i) {
        if (values[i] < 0) ++count;
    }
    return count;
}
```

Подцель 1 — начальный счётчик равен нулю. Подцель 2 — рассматриваем допустимые индексы `[0, n)`: правая граница не включена. Подцель 3 — при подходящем знаке прибавляем единицу, а не само число. Для массива `{-2, 5, -7}` счётчик последовательно принимает значения 1, 1, 2.

При `n == 0` условие цикла сразу ложно. Ни одного обращения к массиву нет. Поэтому наш контракт может разрешить `nullptr` для пустого массива. Это разрешение относится к данному алгоритму, а не ко всем операциям над нулевыми указателями.

Самопроверка S7: сколько раз выполнится тело цикла при `n == 1`? S8: что именно ломается при замене `i < n` на `i <= n`? Сначала ответь словами, затем возвращайся к задаче.

## Что делать, когда застрял

Сначала назови место затруднения: «не понимаю условие», «не знаю конструкцию», «не проходит пример», «не собирается среда». Это четыре разные проблемы. Для условия возьми один маленький вход.
